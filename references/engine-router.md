# 路由与引擎选择

动工前判定走哪条引擎，避免"用 Remotion 硬挂真实组件"或"用真实组件引擎硬做无产品的抽象动效"。

## 决策三问

1. 有没有真实仓库/产品，且要求"真实"？
2. 输入是产品（repo/更新日志）还是提示词（创意/主题/参考）？
3. 要不要复用真实组件当画面？

## 决策表

| 情形 | 引擎 | 理由 |
|---|---|---|
| 有真实产品 + 要真实功能/组件 | A | 真实是核心价值 |
| 有真实产品 + 只要"看起来像"、不想接组件 | B | 用元素 playbook 忠实再现 |
| 无产品 + 提示词/主题驱动 | B | 从零设计元素 |
| 产品片 + 高质量装饰动效 | A + Lottie 通道 | 真组件 + 设计师资产 |

## 选引擎门（四道击穿门，来自开源调研）

引入任何引擎/依赖前，先过四道门：

1. **离线无头 CLI**：能否无头产出 1920×1080@30fps h264（yuv420p、AAC）？
2. **中文文本**：能否高质量渲染中文并跨机可复现？
3. **许可**：是否可接受（AGPL/BSL/非商用须警觉）？
4. **维护**：是否活跃可托付（push 脉搏 + 发版节奏，星数仅参考）？

任何一道不过，就出局或降级为"记录性参考"。

## 引擎适配契约（借鉴 html-video）

如果未来要加第三条引擎（如 HyperFrames 无头渲染、Revideo），遵循同一契约：

```ts
render(input, ctx) → output
// input：统一的分镜/方向输入（方向文件 / 设计契约 / 时间轴）
// ctx：引擎上下文（画幅、帧率、资产路径、scope）
// output：MP4 + 可复现工程 + 交付证据
```

共享层（方向/契约/时间轴）不绑定引擎；引擎只负责把同一份方向"翻译"成各自的实现。
