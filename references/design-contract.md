# 设计契约：把方向写成具体值

方向定性，契约定量。契约是一份"每行可检查"的具体值清单，两引擎通用；它写在哪、怎么落地由引擎决定（引擎 A → `DIRECTION.md` 第 9 节 + tokens；引擎 B → `src/spec.ts` 顶部契约 + `FILM` + 三账本常量）。

> 来源：motion-design 的 Stage 2/4 方法论（其强项），补 guizang 的"画面规范"。

## 契约字段（九项，缺一不可）

| 字段 | 写什么 | 例子 |
|---|---|---|
| palette | hex + 角色（主/次/强调/背景/前景），3–5 色 | `accent #3b82f6 预告下一个场景` |
| type | 家族 + 字重 + 字号 + 字距；中英文各给；payoff 词用最重字重最大字号 | 中文 Noto Sans SC，英文 Geist |
| marks | 线/填充/形状怎么画（SVG 手法） | 描线策略、圆角、端点 |
| texture-light | 逐元素材质 + 光来源 | 纸/墨分层，光画成形状 |
| composition | 占位率、留白、边距规则 | 边缘 150px/90px 内无静止元素 |
| motion | 每类移动的 easing | 入场 EASE.out，回弹只用于… |
| transition | 哪个机制换哪个场景 | 硬切/遮罩/匹配剪辑 |
| sound | 声音调色板 | 乐器、音色、氛围 |
| bans | 本片不用什么 | 不用彩虹色、不用回弹、不用 lens flare |

## 写法纪律

1. **写值，不写形容词**。"高端"无效；`#0f172a 底色 + Inter 800 72px 标题 + EASE.out 0.4s 入场` 有效。
2. **每个选择可溯源**到产品/主题/提示词。写不出"为什么"的值，删掉。
3. **元素先设计后动效**：先把每个元素按 `element-playbooks.md` 设计成静态好构图（frame 0、每场景首帧、末帧），再做动效。弱静态救不回动效。
4. **先出静帧再看代码**：文件宿主里先渲染关键帧、逐帧 zoom 看字号/脸/手/道具/数据标签，再继续。

## 与方向文件的关系

- 引擎 A：方向文件 `DIRECTION.md` 第 9 节（画面规范）就是契约；此处字段补全其 texture/sound/bans。
- 引擎 B：`src/spec.ts` 顶部契约 + `FILM` + 三账本常量（`// S07` `// E03` `// S31 X02`）。
